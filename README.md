# Приём документов соискателей

Сервис принимает документы соискателей с телефона, сам вычитывает из них данные локальной моделью и отдаёт оператору карточку на проверку. Персональные данные не покидают контур: модель (Qwen3.8) работает в локальной инфраструктуре, внешних облачных сервисов нет.

## Что внутри

- **Страница соискателя** (`web/applicant`, React): страна → набор документов → загрузка файлов → статусы по каждому документу → дозагрузка в ту же заявку.
- **Рабочее место оператора** (`web/operator`, React): вход через Keycloak, список заявок с фильтрами, карточка «изображение + поля с цветом уверенности», правка поля, повторный разбор, история, раздел «В работе».
- **API** (`backend/`, FastAPI): все проверки входящего, BFF для входа операторов, отдача файлов только с сессией.
- **Воркер** (тот же образ, `python -m app.queue.worker`): очередь задач в PostgreSQL, разбор документа моделью через `backend/app/llm/`.
- **PostgreSQL** — заявки, поля, очередь `jobs`, журнал аудита; **SeaweedFS (S3)** — файлы; **Keycloak** — вход операторов; **Caddy** — единственная точка входа (HTTPS).

Схема — [docs/architecture.md](docs/architecture.md).

## Требования к машине

- **Linux** с Docker 24+ и Docker Compose v2, либо **Windows 10/11** с Docker Desktop (WSL2) и Git for Windows (Git Bash).
- Минимум 4 CPU, 8 ГБ RAM, 20 ГБ диска (без локальной модели).
- Свободные порты 80 и 443 на машине.
- Сетевой доступ к адресу модели (по умолчанию `llm.ilons.ru`).
- Python 3 (для `make secrets`) и, по желанию, `make`. Без `make` все команды можно выполнить напрямую (они указаны ниже).
- Для локальной модели на своей GPU — [docs/local-model.md](docs/local-model.md).

## Запуск с нуля

Команды одинаковы для Linux и Git Bash на Windows.

```bash
git clone <адрес репозитория> hr-docs && cd hr-docs
cp .env.example .env
# Откройте .env и впишите:
#   LLM_API_KEY   — ключ доступа к модели (выдают организаторы)
#   OCR_API_TOKEN — только если OCR-сервис требует токен
# Адрес стенда можно не трогать: make secrets подставит https://localhost.
make secrets            # или: python scripts/gen_secrets.py — заполнит пустые пароли и ключи, существующие значения не трогает
docker compose up -d --build
docker compose ps       # все сервисы healthy; первый старт Keycloak — 1–2 минуты
```

Для стенда по IP или домену задайте в `.env` до `make secrets`:
`PUBLIC_BASE_URL=https://<адрес>`, `SITE_ADDRESS=<адрес>`, `OIDC_ISSUER=https://<адрес>/kc/realms/hr`, `CADDY_TLS=internal` (самоподписанный сертификат) или email для Let's Encrypt.

Важно:

- Init-скрипт PostgreSQL (`infra/postgres/init/01-init.sh`, создаёт БД и роли) выполняется **только на пустом volume**. Если вы поменяли пароли БД в `.env` после первого запуска, их нужно поменять и в самой БД — или пересоздать volume (`docker compose down -v` **удалит все данные**).
- Realm Keycloak импортируется из `infra/keycloak/realm-hr.json` при первом старте; если realm уже есть, импорт пропускается.
- Миграции схемы БД применяются автоматически при старте api.

## Что должно получиться

| Что                                       | Адрес                                                                                                                                                     |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Страница соискателя        | `https://localhost/`                                                                                                                                         |
| Рабочее место оператора | `https://localhost/operator/`                                                                                                                                |
| Проверка API                         | `https://localhost/api/healthz` → `{"status":"ok"}`                                                                                                       |
| Письма стенда (Mailpit)          | только с машины стенда: http://127.0.0.1:8025 (на удалённом стенде —`ssh -L 8025:127.0.0.1:8025 <стенд>`)          |
| Админка Keycloak                      | только с машины стенда: http://localhost:8081/kc/admin (на удалённом стенде —`ssh -L 8081:127.0.0.1:8081 <стенд>`) |

При `CADDY_TLS=internal` браузер предупредит о самоподписанном сертификате — это ожидаемо для стенда без домена. Снаружи открыты только 80 и 443; админка Keycloak по `https://localhost/kc/admin` отдаёт 404.

## Учётные данные для входа

Войти можно по логину или по email. Пароль у всех тестовых операторов один — значение `KC_DEMO_PASSWORD` из вашего `.env` (его генерирует `make secrets`; в репозиторий пароли не пишутся — правило проекта и условие Д9). Показать его:

```bash
grep '^KC_DEMO_PASSWORD=' .env
```

| Логин | Email | Роль | Офис | Что может |
|---|---|---|---|---|
| `reader.msk` | `reader.msk@example.test` | doc-reader | Москва | смотреть заявки |
| `editor.msk` | `editor.msk@example.test` | doc-editor | Москва | + править поля, разбирать повторно, выгружать, заводить операторов своего офиса |
| `editor.spb` | `editor.spb@example.test` | doc-editor | Санкт-Петербург | то же для своего офиса |
| `supervisor` | `supervisor@example.test` | supervisor | все | всё, включая «Сотрудники» |

Администратор Keycloak — значения `KC_BOOTSTRAP_ADMIN_USERNAME` / `KC_BOOTSTRAP_ADMIN_PASSWORD` из `.env`.

## Проверка за 3 минуты

1. Откройте `https://localhost/`, выберите страну «Россия», введите ФИО и email, отметьте согласие → «Продолжить».
2. Загрузите `data/test_1/01_Россия_Алексеева/паспорт.jpg` в слот «Паспорт РФ» — файл сразу получает «принят» или «отклонён: причина». Тот же файл второй раз → «Этот файл уже загружен».
3. Нажмите «Отправить комплект» — сразу появится номер заявки, статусы документов обновляются без перезагрузки страницы (опрос раз в 2 с): «принят» → «разбирается» → «готово» / «есть замечания» / «не прочитался» / «ошибка разбора».
4. Откройте `https://localhost/operator/`, войдите как `editor.msk`. В списке — новая заявка; в карточке — изображение страницы и поля с цветом (зелёный / жёлтый / красный). Исправьте поле — правка сохранится с пометкой «правка оператора» и появится во вкладке «История».
5. Раздел «В работе» — сколько задач ждёт, разбирается, разобрано за час, среднее время.
6. Без входа данные не открываются:
   ```bash
   curl -k -s -o /dev/null -w "%{http_code}\n" https://localhost/api/operator/applications   # 401
   ```

## Переключение модели

Поменять `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` в `.env` и пересоздать воркер: `docker compose up -d worker`. Подробно (vLLM на своей GPU) — [docs/local-model.md](docs/local-model.md).

## Развёртывание на сервере с доменом

Чтобы судьи открывали стенд с телефона по нормальному адресу с настоящим сертификатом. Всё переключается через `.env`, код не меняется. Ниже `<IP>` — адрес сервера, `<домен>` — имя для него.

**Домен без покупки:** `<IP-с-дефисами>.sslip.io` (например, адрес `1.2.3.4` → домен `1-2-3-4.sslip.io`), запасной вариант — `nip.io`. Это только DNS: имя указывает прямо на наш сервер, трафик через третьи стороны не идёт. Туннели вроде ngrok или cloudflared **не используем**: через них пошли бы персональные данные.

1. **Порты.** Снаружи должны быть открыты 80 (выпуск сертификата Let's Encrypt) и 443. Проверка с любой машины:
   ```bash
   curl -m 5 -sS -o /dev/null -w "%{http_code}\n" http://<IP>    # любой HTTP-код = порт открыт; таймаут = закрыт
   ```

   Если порты закрыты, откройте их в настройках сервера или облака. Если открыть нельзя — см. шаг 6.
2. **Код на сервер:**
   ```bash
   ssh <пользователь>@<IP>
   git clone <адрес репозитория> ~/hr_docs && cd ~/hr_docs
   # или с ноутбука без доступа сервера к git: git archive HEAD | ssh <пользователь>@<IP> "mkdir -p ~/hr_docs && tar -x -C ~/hr_docs"
   ```
3. **`.env` на сервере — новые секреты, не копия с ноутбука:**
   ```bash
   cp .env.example .env && chmod 600 .env
   # впишите в .env:
   #   PUBLIC_BASE_URL=https://<домен>
   #   SITE_ADDRESS=<домен>
   #   OIDC_ISSUER=https://<домен>/kc/realms/hr
   #   CADDY_TLS=<email команды>        # Caddy сам получит сертификат Let's Encrypt
   #   LLM_API_KEY=<ключ модели>        # единственное значение, которое переносится вручную
   python3 scripts/gen_secrets.py      # = make secrets: заполнит пустые секреты случайными значениями
   ```
4. **Запуск:** `docker compose up -d --build`. Первый старт — несколько минут: сборка образов, импорт realm, выпуск сертификата. Следить: `docker compose ps`, `docker compose logs -f caddy`.
5. **Проверка:** откройте `https://<домен>/` (соискатель) и `https://<домен>/operator/` (вход через Keycloak). Браузер не должен показывать предупреждений о сертификате.
6. **Если 80/443 открыть нельзя:** поставьте `CADDY_TLS=internal`, `PUBLIC_BASE_URL=https://localhost`, `SITE_ADDRESS=localhost`, `OIDC_ISSUER=https://localhost/kc/realms/hr` и ходите на стенд через SSH-туннель: `ssh -L 443:localhost:443 <пользователь>@<IP>`, затем `https://localhost` на своей машине (сертификат самоподписанный).
7. **Модель на том же сервере (vLLM, профиль `llm-local`):** воркер ходит к ней напрямую по внутренней сети Docker: `LLM_BASE_URL=http://vllm:8000/v1` (см. [docs/local-model.md](docs/local-model.md)), затем `docker compose up -d worker`.

**Важно про Keycloak:** realm `hr` импортируется из `infra/keycloak/realm-hr.json` **только на чистой БД**. В нём зашиты адрес стенда (redirect URI, issuer) и пароли тестовых операторов. Поэтому при смене адреса стенда либо поднимайте стенд на новом volume (`docker compose down -v` **удалит все данные**), либо поправьте redirect URI и web origins клиента `operator-bff` в админке Keycloak (через туннель `make kc-admin-tunnel-help`).

## Частые проблемы

- **Порт 80 или 443 занят** (Windows: IIS, Skype, другой веб-сервер) — освободите порт, затем `docker compose up -d caddy`.
- **Keycloak долго стартует** — первый запуск до 2 минут; api ждёт, пока Keycloak станет healthy. Смотрите `docker compose logs keycloak`.
- **Realm не обновился после правки `realm-hr.json`** — импорт пропускается, если realm уже есть: удалите realm в админке Keycloak или пересоздайте volume `docker compose down -v` (**удалит все данные**).
- **Ошибка конфигурации при старте api** — в логе (`docker compose logs api`) перечислены незаданные переменные; запустите `make secrets` и проверьте `.env`.
- **Модель недоступна** — документы получают статус «ошибка разбора» с причиной; задачи повторяются с увеличивающейся паузой, после исчерпания попыток оператор нажимает «Разобрать повторно».
- **Windows: «bad interpreter» в контейнерах** — файлы `.sh` должны быть с LF; в репозитории это закреплено `.gitattributes`. Если копия получена не через `git clone` (архив, копирование), склонируйте репозиторий заново.
