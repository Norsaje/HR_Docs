## 1. Модель читает и извлекает за один вызов; правильность подтверждает код, а не модель

- **Решение:** Qwen3.8-27B (мультимодальная) извлекает поля по JSON-схеме прямо из изображения — один вызов на страницу. Цвет поля ставит детерминированный код: правила реестра и контрольные суммы. Самооценке модели («уверенность 0–100») не доверяем.
- **Варианты:**
  - классический OCR → текст → LLM;
  - только VLM, цвет по самооценке модели;
  - VLM + независимый OCR (olmOCR) + арбитр по вырезке + сверка (план спецификации).
- **Почему так в сданной версии:** из-за времени оставили один проход модели. Второй источник (olmOCR) проверили экспериментом, но в пайплайн не включили. Чтобы не было «ложных зелёных», зелёный ставится только когда значение подтверждено независимой проверкой — контрольной суммой ИНН/СНИЛС или совпадением с текстовым слоем PDF — и напечатано (не от руки, не в штампе). Всё, что подтвердить нечем, — жёлтое.
  - Эксперимент 2 (20 документов: паспорт РФ, СНИЛС, ИНН, патент): 20/20 ответов по схеме без повторов, вид документа определён верно 20/20, p50 13,0 с, p95 18,0 с на документ.
  - Эксперимент 1 (13 документов РФ): olmOCR хорошо читает кириллицу (доля кириллицы в тексте 79–100%; 36/36 частей ФИО, прочитанных Qwen, нашлись в тексте OCR; номера СНИЛС/ИНН совпали у двух источников 7/7). То есть второй источник готов к подключению.
- **Риски:** без второго источника большинство полей жёлтые, и оператору больше работы. olmOCR медленнее Qwen (p50 21 с, p95 34 с против 13 с), поэтому при подключении проходы надо запускать параллельно.

## 2. Очередь — своя таблица `jobs` в PostgreSQL

- **Решение:** задачи в той же БД, постановка в одной транзакции с файлом, захват `FOR UPDATE SKIP LOCKED`, аренда + heartbeat, reaper возвращает зависшие задачи, повтор с backoff.
- **Варианты:** Celery + Redis; Procrastinate; RQ.
- **Почему:**
  - нет окна потери между «файл записан» и «задача поставлена»;
  - на один сервис меньше;
  - код очереди короткий, его можно объяснить и показать на защите (`docker compose kill worker` → задачи доходят после `up -d worker`).
- **Риски:** не для тысяч задач в секунду — не наш масштаб.

## 3. Вход операторов — Keycloak + BFF

- **Решение:** OIDC Authorization Code + PKCE. FastAPI — конфиденциальный клиент, токены не попадают в браузер, у браузера только HttpOnly-cookie серверной сессии. Роли — клиентские роли Keycloak, офисы — группы.
- **Варианты:** свой логин с паролями в БД; SPA с токенами в браузере; Zitadel или Authentik.
- **Почему:** BFF рекомендован для браузерных приложений с ПДн (RFC 10017 / BCP 212). MFA, passkeys и блокировка перебора — из коробки. Новый сотрудник заводится без кода.
- **Проверено** (Keycloak 26.3.5): realm импортируется сам, плейсхолдеры `${...}` подставляются (обмен кода прошёл с секретом клиента из `.env`); все четыре тестовых оператора входят через форму (`scripts/kc_login_check.py`), роли приходят в `resource_access.operator-bff.roles`, офисы — в `groups`. Discovery изнутри сети отдаёт публичные `issuer` и `authorization_endpoint` и внутренние `token_endpoint` и `jwks_uri` — благодаря `--hostname-backchannel-dynamic=true`, поэтому `OIDC_TOKEN_ENDPOINT` и `OIDC_JWKS_URI` можно не задавать.
- **Риски:** лишний сервис и настройка hostname. У пользователя без групп (`supervisor`) claim `groups` отсутствует — читаем как пустой список.

## 4. Только локальные модели, переключение адресом в конфиге

- **Решение:** основная модель — Qwen3.8 на llm.ilons.ru (развёрнута в контуре), запасная — vLLM на своей GPU (профиль `llm-local`, `docs/local-model.md`). Внешних облачных API нет. Все вызовы — только через `backend/app/llm/`; провайдер выбирается словарём по `LLM_PROVIDER`.
- **Варианты:** внешний сервис (GigaChat и т. п.) для разработки и локальная модель для показа; только своя GPU.
- **Почему:** заказчик требует не отдавать ПДн наружу. Один OpenAI-совместимый адаптер покрывает и llm.ilons.ru, и vLLM. Thinking выключен (`chat_template_kwargs.enable_thinking=false`): в ответах не больше 980 токенов и нет блоков `<think>` — иначе документ занимал бы минуты.
- **Риски:** зависим от сервера, который поддерживает сотрудник. Профиль vLLM на A10 **не проверен** (стенд разработки без GPU) — `docs/limitations.md`. П. 5.3.4 кейса просит «внешний + локальный»: механизм сменного провайдера реализован, внешний исключён сознательно.

## 5. Реестр документов в YAML

- **Решение:** страны, документы, поля и правила — в `registry/documents.yaml`. Из него строятся набор документов по стране, JSON-схема модели, описание полей в промпте, правила и карточка оператора.
- **Варианты:** код на каждый вид документа; таблицы в БД с админкой.
- **Почему:** новое поле или правило — одна правка и перезапуск (правка на защите за минуты). Виды документов из открытого набора (ВУ РФ, ВУ Киргизии, паспорт Беларуси, паспорт Индии) добавлены только правкой YAML, без нового кода.
- **Риски:** ошибка в YAML ловится Pydantic-валидацией при старте с номером строки. Это уже сработало: в исходном реестре подпись поля патента с запятой без кавычек YAML молча разрезал на два ключа, загрузчик остановил запуск на строке 215.

## 6. JSON-схема в декодере — только форма; правила — после генерации

- **Решение:** structured outputs гарантируют ключи и типы, у каждого поля есть статус `ok | unreadable | absent`. Регулярки, контрольные суммы и даты проверяет код. Ответ проверяется той же схемой (`jsonschema`); в тексте ошибки — только путь и нарушенное правило, без значения (оно может быть ПДн).
- **Варианты:** строгие `pattern` в схеме; свободный текст + парсинг.
- **Почему:** строгий шаблон в декодере заставляет модель дорисовать цифры на смазанном фото; право сказать «не вижу» снижает галлюцинации.
  - Эксперимент 3: llm.ilons.ru принял схемы всех восьми видов спецификации в режиме `json_schema` (`["string","null"]`, `enum` с `null`, `minItems/maxItems`), 8/8 ответов по схеме; запасные режимы `json_object` и `prompt` тоже работают. На чужом документе модель честно отвечает `doc_type=other`.
- **Риски:** поддержка схем различается у серверов — предусмотрен автоматический переход `json_schema → json_object → prompt` при ответе 400 про `response_format`.

## Рабочие решения

- **Миграции — SQL-файлы `backend/app/db/migrations/*.sql`, применяются при старте api под `hr_owner`** (вместо Alembic — ради скорости разработки; порядок по имени файла, применённые записываются в служебную таблицу).
- **Статусы соискателю — опросом `GET` раз в 2 с вместо SSE**: проще и надёжнее за прокси; задержка до 2 с приемлема.
- **Caddy: блокировка `/kc/admin` и `/kc/realms/master` — через `handle`, а не голый `respond`** (Caddy выполняет `handle` раньше `respond`; в варианте из спецификации `/kc/realms/master` снаружи отдавал 200). Проверено: снаружи 404.
- **Разработка на Windows**: `.gitattributes` с `eol=lf` и бит `+x` у shell-скриптов в git, иначе init-скрипты ломаются в Linux-контейнерах.
