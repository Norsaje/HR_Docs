# 06. Восемь видов документов: поля, правила, алгоритмы

Источник истины — `registry/documents.yaml`. Здесь объяснение и алгоритмы. Правила кейса — минимум; добавленные правила либо ловят ошибку распознавания без модели, либо ловят реальную проблему документа.

Обозначения: **М** — «минимум полей» (без них документ не разобран), **Т** — тип нормализации.

## Набор документов по стране

| Группа | Страны | Документы |
|---|---|---|
| `ru` | RU | Паспорт РФ (главный разворот), СНИЛС, ИНН |
| `uz` | UZ | Паспорт гражданина Узбекистана, Миграционная карта, Патент на работу |
| `eu` | 27 стран ЕС | Удостоверение личности или загранпаспорт ЕС, Вид на жительство |

Страна не из реестра → `COUNTRY_NOT_SUPPORTED` на сервере.

## 1. Паспорт РФ — `ru_passport`

| Поле | Название | Т | М | Правила |
|---|---|---|---|---|
| series | Серия | digits(4) | да | ровно 4 цифры |
| number | Номер | digits(6) | да | ровно 6 цифр |
| surname | Фамилия | name | да | только кириллица, дефис |
| given_name | Имя | name | да | то же |
| patronymic | Отчество | name | нет | то же |
| sex | Пол | enum М/Ж | нет | |
| birth_date | Дата рождения | date | да | не в будущем |
| birth_place | Место рождения | text | нет | |
| issued_by | Кем выдан | text | нет | |
| issue_date | Дата выдачи | date | нет | не в будущем; не раньше 14-летия |
| department_code | Код подразделения | code | нет | `^\d{3}-\d{3}$` |

- **Межпольное правило** `ru_passport_age_validity` (`warning`). По постановлению Правительства РФ № 828 паспорт, выданный до 20 лет, действует до 20 лет; выданный до 45 — до 45 лет; дальше — бессрочно (плюс 90 дней на замену). Если сегодня возраст ≥ 20, а паспорт выдан до 20 лет (или то же для 45) → «Паспорт, вероятно, подлежал замене в {age} лет».
- **Разворот.** На странице 2 — кем выдан, дата и код подразделения; на странице 3 — фото, ФИО, пол, дата и место рождения, МЧЗ (с 2011 года). Серия и номер напечатаны вертикально по краю — для них арбитр поворачивает вырезку.
- **МЧЗ паспорта РФ** (`mrz: ru_internal`), 2 строки по 44 символа:
  - строка 1: `PNRUS` + фамилия`<<`имя`<`отчество в русской МЧЗ-транслитерации, добито `<`;
  - строка 2, позиции 1–9: первые 3 цифры серии + 6 цифр номера; 10 — контрольная; 11–13 `RUS`; 14–19 дата рождения `YYMMDD`; 20 — контрольная; 21 — пол `M/F`; 22–28 — `<` (срока действия нет); 29–42 — 4-я цифра серии + дата выдачи `YYMMDD` + код подразделения 6 цифр + `<`; 43 — контрольная по 29–42; 44 — композитная по 1–10, 14–20, 22–43.
  - Синтетический пример (серия 4509, номер 123456, рождение 01.01.1980, выдан 10.10.2009, код 770-001): `4501234568RUS8001014M<<<<<<<9091010770001<50`.
  - **Формат сверь с реальным образцом из открытого набора в фазе 2.** Если позиции расходятся, проверяй только номер, дату рождения и их контрольные цифры, а расхождение запиши в `docs/limitations.md`.
  - Таблица транслитерации ФИО в МЧЗ РФ: `А A, Б B, В V, Г G, Д D, Е E, Ё 2, Ж J, З Z, И I, Й Q, К K, Л L, М M, Н N, О O, П P, Р R, С S, Т T, У U, Ф F, Х H, Ц C, Ч 3, Ш 4, Щ W, Ъ X, Ы Y, Ь 9, Э 6, Ю 7, Я 8`. Тоже проверить на образце; если не сходится — сверять ФИО с МЧЗ не обязательно (это P1).

## 2. СНИЛС — `snils`

| Поле | Т | М | Правила |
|---|---|---|---|
| number | digits(11) | да | 11 цифр, формат показа `XXX-XXX-XXX YY`; контрольное число |
| surname, given_name, patronymic | name | нет | |

Бывает в двух видах: зелёная карточка (до 01.04.2019) и уведомление АДИ-РЕГ (бумага или PDF). В PDF с Госуслуг есть текстовый слой.

**Контрольное число СНИЛС** (`checksums.snils_ok`). Проверяется только для номеров больше `001-001-998`. Цифры 1–9 умножаются на веса 9, 8, …, 1 и суммируются:

- сумма < 100 → контрольное = сумма;
- сумма 100 или 101 → `00`;
- сумма > 101 → остаток от деления на 101, а если остаток 100 → `00`.

| Номер | Ожидаемое контрольное | Комментарий |
|---|---|---|
| `112-233-445 95` | 95 | сумма 95 < 100 |
| `123-456-789 64` | 64 | сумма 165 → 165 mod 101 = 64 |
| `087-654-303 00` | 00 | граничный случай |
| `123-456-789 65` | — | **невалиден** |

## 3. ИНН физлица — `inn`

| Поле | Т | М | Правила |
|---|---|---|---|
| number | digits(12) | да | 12 цифр; два контрольных разряда |
| surname, given_name, patronymic | name | нет | |
| issue_date | date | нет | не в будущем |

С 01.12.2022 свидетельство выдаётся в электронном виде (PDF с подписью ФНС) — текстовый слой главнее OCR.

**Контрольные разряды ИНН-12** (`checksums.inn12_ok`):

- `n11 = (Σ d[i]·w1[i], i=1..10) mod 11 mod 10`, `w1 = 7,2,4,10,3,5,9,4,6,8`;
- `n12 = (Σ d[i]·w2[i], i=1..11) mod 11 mod 10`, `w2 = 3,7,2,4,10,3,5,9,4,6,8`.

| ИНН | Валиден |
|---|---|
| `500100732259` | да |
| `123456789047` | да |
| `770708389324` | да |
| `500100732250` | нет |
| `123456789048` | нет |

## 4. Паспорт гражданина Узбекистана — `uz_passport`

| Поле | Т | М | Правила |
|---|---|---|---|
| number | code | да | `^[A-Z]{2}\d{7}$` (`warning`, если не так) |
| surname | latin_name | да | латиница |
| given_name | latin_name | да | латиница |
| patronymic | latin_name | нет | |
| birth_date | date | нет | не в будущем |
| sex | enum M/F | нет | |
| nationality | code | нет | `UZB` |
| personal_number | digits(14) | нет | ПИНФЛ, 14 цифр |
| issue_date | date | нет | не в будущем |
| expiry_date | date | нет | **не истёк** (`error`), позже даты выдачи |

Это загранпаспорт с МЧЗ TD3 (2×44) или ID-карта с 2021 года: TD1, 3×30, две стороны — грузятся двумя файлами в один документ. В реестре `mrz: [td3, td1]`.

- Синтетический TD3: `P<UZBTOSHMATOV<<BOBUR<<<<<<<<<<<<<<<<<<<<<<<` / `FA12345673UZB9503157M30031493150395012345632`.
- Узбекская латиница: `O‘ G‘ Sh Ch Ng` и апостроф-ʻ. В МЧЗ апострофы опускаются (`O'` → `O`). Все варианты апострофа (`ʻ ’ ‘ ' \``) нормализуем к `'`.

## 5. Миграционная карта — `migration_card`

| Поле | Т | М | Правила |
|---|---|---|---|
| series | code | нет | |
| number | digits | да | 7–10 цифр (`warning`, если не так) |
| entry_date | date | нет | **не в будущем** (`error`) |
| stay_until | date | нет | «действует до» = «срок пребывания до»; не раньше даты въезда; истёк → `warning` «Срок пребывания истёк» |
| surname, given_name | name/latin_name | нет | для сверки |
| passport_number | code | нет | для сверки с паспортом |
| visit_purpose | enum | нет | `work, private, study, tourism, business, other` |

МЧЗ нет. Даты часто вписаны от руки, дата въезда — в штампе пограничника. Поэтому `kind=handwritten|stamp`, и по умолчанию поле жёлтое.

## 6. Патент на работу — `work_patent`

| Поле | Т | М | Правила |
|---|---|---|---|
| series | code | нет | обычно 2 цифры кода региона |
| number | digits | да | |
| issue_date | date | нет | не в будущем |
| valid_until | date | да | **не истёк** (`error`); позже даты выдачи; не позже даты выдачи + 12 мес. (`warning`) |
| region | text | нет | «г. Москва», «Московская область»… |
| surname, given_name | name/latin_name | нет | для сверки (на бланке кириллица и латиница) |
| passport_number | code | нет | для сверки |
| inn | digits(12) | нет | если указан — контрольная сумма |

Срок патента определяется оплаченными авансами НДФЛ (1–12 месяцев), на бланке поля «действует до» может не быть. Тогда модель вернёт `absent`, документ уйдёт в `needs_review` с замечанием: «На бланке патента не указан срок действия — уточните по чекам об оплате НДФЛ». Это открытый вопрос к организаторам.

## 7. Удостоверение личности или паспорт ЕС — `eu_id`

| Поле | Т | М | Правила |
|---|---|---|---|
| doc_kind | enum `id_card/passport` | нет | |
| number | code | да | |
| surname | latin_name | да | **только латиница** (Unicode Latin, диакритика допустима; кириллица или греческий в имени → `error`, кроме греческого документа с латинской транслитерацией) |
| given_names | latin_name | да | то же |
| birth_date | date | нет | не в будущем |
| nationality | code | нет | ISO 3166-1 alpha-3 (Германия в МЧЗ — `D`); не из ЕС → `warning` |
| expiry_date | date | нет | **не истёк** (`error`) |

МЧЗ: TD1 (ID-карта, 3×30) или TD3 (паспорт). Сравнение имени с МЧЗ — после транслитерации диакритики по ICAO 9303 (`Ä→AE` или `A`, `Ö→OE` или `O`, `Ü→UE` или `U`, `ß→SS`, `Ø→OE`, `Å→AA`; допускаем оба варианта).

## МЧЗ ICAO 9303 (`app/registry/mrz.py`, свой код, ~150 строк)

- **Значения символов:** `0–9` → 0–9, `A–Z` → 10–35, `<` → 0. Веса 7, 3, 1 по кругу, сумма mod 10.
- **TD3, строка 2:**

  | Позиции | Содержимое |
  |---|---|
  | 1–9 | номер |
  | 10 | контрольная |
  | 11–13 | гражданство |
  | 14–19 | дата рождения |
  | 20 | контрольная |
  | 21 | пол |
  | 22–27 | срок действия |
  | 28 | контрольная |
  | 29–42 | персональный номер |
  | 43 | контрольная |
  | 44 | композитная по 1–10, 14–20, 22–43 |

- **TD1:**
  - строка 1: тип 1–2, страна 3–5, номер 6–14, контрольная 15, доп. данные 16–30;
  - строка 2: рождение 1–6, контрольная 7, пол 8, срок 9–14, контрольная 15, гражданство 16–18, доп. 19–29, композитная 30 по стр.1 6–30 + стр.2 1–7, 9–15, 19–29;
  - строка 3: имя.
- **Годы:** рождение `YY` → век, при котором дата ≤ сегодня; срок → `20YY`.
- **Тестовые векторы** (образцы ICAO 9303):
  - TD3: `P<UTOERIKSSON<<ANNA<MARIA<<<<<<<<<<<<<<<<<<<` / `L898902C36UTO7408122F1204159ZE184226B<<<<<10` — все контрольные сходятся (номер 6, рождение 2, срок 9, персональный 1, композит 0);
  - TD1: `I<UTOD231458907<<<<<<<<<<<<<<<` / `7408122F1204159UTO<<<<<<<<<<<6` / `ERIKSSON<<ANNA<MARIA<<<<<<<<<<` — номер 7, рождение 2, срок 9, композит 6;
  - испорченный вектор: замени в TD3 `L898902C3` на `L898902C8` — контрольная номера должна не сойтись.
- **Исправление OCR-путаниц только в позициях, где по формату ожидаются цифры:** `O→0`, `I→1`, `B→8`, `S→5`, `Z→2`. Применяется только если после замены сходится контрольная цифра. Это подсказка, значение не меняется.

## Даты (`app/registry/dates.py`)

- **Форматы:**
  - `DD.MM.YYYY`, `DD.MM.YY`, `DD/MM/YYYY`, `DD-MM-YYYY`, `YYYY-MM-DD`;
  - `DD MMM YYYY` с русскими и английскими сокращениями месяцев и двуязычными вариантами вида `12 JAN/ЯНВ 1990`;
  - `«12» января 1990 г.`;
  - даты МЧЗ `YYMMDD`.
- **Невалидная дата** (`31.02.2020`) → `rule_fail` «Некорректная дата».
- **«Сегодня»** считается в `APP_TIMEZONE`.
- **Обязательные тесты:**

  | Вход | Результат |
  |---|---|
  | `12.01.1990` | `1990-01-12` |
  | `12 JAN/ЯНВ 90` | `1990-01-12` |
  | `«3» марта 2015 г.` | `2015-03-03` |
  | `31.02.2020` | ошибка |
  | `01.01.30` для даты рождения | `1930-01-01` |
  | `01.01.30` для срока | `2030-01-01` |

## Имена и транслитерация (`names.py`, `translit.py`)

- **Нормализация:** верхний регистр, `Ё→Е`, апострофы → `'`, двойные пробелы → один.
- **Кириллица → латиница по ICAO 9303** (для сверки между документами): `А A, Б B, В V, Г G, Д D, Е E, Ё E, Ж ZH, З Z, И I, Й I, К K, Л L, М M, Н N, О O, П P, Р R, С S, Т T, У U, Ф F, Х KH, Ц TS, Ч CH, Ш SH, Щ SHCH, Ъ IE, Ы Y, Ь —, Э E, Ю IU, Я IA`.
- **Узбекская латиница:** `O'→O`, `G'→G`; `SH`, `CH` сохраняются.
- **Сравнение:** Jaro–Winkler по нормализованной латинице; пороги в `.env` (`NAME_MATCH_THRESHOLD=0.92`).
