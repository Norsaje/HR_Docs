# 01. Продукт: что строим и зачем

## Задача

Соискатель (в том числе иностранный гражданин) с телефона загружает комплект документов. Сервис сам вычитывает поля и проверяет их по правилам. Оператор агентства получает готовую карточку на проверку, а не на перепечатывание.

Главная ценность для оператора — цвет поля:

- **зелёное** — подтверждено независимыми проверками, перепроверять не нужно;
- **жёлтое** — стоит взглянуть;
- **красное** — точно нужен человек.

Цель — ноль «ложных зелёных».

## Роли

| Роль | Как входит | Что делает |
|---|---|---|
| Соискатель | Без регистрации. Вводит страну, ФИО, email и даёт согласие на обработку ПДн | Загружает документы, видит статус каждого, дозагружает в ту же заявку |
| Оператор `doc-reader` | Keycloak (OIDC), только своя группа (офис) | Смотрит заявки, карточки, оригиналы, раздел «В работе», историю |
| Оператор `doc-editor` | Keycloak, только своя группа | Всё, что `doc-reader`, плюс правка полей, повторный разбор, «проверено», запрос документов, выгрузки |
| `supervisor` | Keycloak, все группы | Всё, плюс журнал системы, сотрудники, удаление данных соискателя |

Email соискателя нужен только для обратной связи: ссылка на заявку и уведомления. Пароля и личного кабинета у соискателя нет.

## Сценарий соискателя

1. Открывает ссылку офиса `/apply/<office_slug>` (или `/`, тогда офис по умолчанию).
2. Выбирает страну, вводит ФИО и email, ставит галочку согласия (по умолчанию не отмечена). Рядом ссылки на текст согласия и политику обработки ПДн.
3. Видит список документов для своей страны с подсказками, как снимать.
4. Загружает файлы: можно снять камерой или выбрать из галереи, на один документ — несколько файлов. По каждому файлу сразу видит «принят» или «отклонён» с причиной.
5. Нажимает «Отправить комплект» и сразу получает подтверждение с номером заявки. Ссылка на заявку приходит на email.
6. Без перезагрузки страницы видит по каждому документу: принят → разбирается (этап) → готово / есть замечания / не прочитался (причина и совет) / ошибка разбора (повторим автоматически).
7. Видит, чего не хватает, и дозагружает в ту же заявку: по ссылке из письма или с того же устройства.

## Сценарий оператора

1. Входит через Keycloak.
2. Видит список заявок своей группы с фильтрами: статус, страна, есть ошибки, истекает в ближайшие N дней, поиск, даты.
3. Открывает карточку. Слева документы, в центре оригинал, справа поля. При выборе поля на оригинале подсвечивается его рамка.
4. Видит цвет каждого поля и, по клику, варианты всех источников (Qwen, OCR, арбитр, МЧЗ), а также подсказку по контрольной сумме.
5. Правит поле. Правка сохраняется с пометкой «правка оператора: ФИО, время», правила перепроверяются сразу.
6. Видит все замечания по документам и сверку между документами.
7. Отправляет документ на повторный разбор или отмечает его проверенным.
8. В разделе «В работе» видит реальное состояние очереди из БД: сколько ждёт, что разбирается и каким воркером, что упало и почему, среднее время.

### P1 — бонусы кейса (+10 баллов, только при закрытом P0) и качество

1. Система сама сообщает соискателю, чего не хватает, и просит дослать: email и экран заявки.
2. Уверенность по каждому полю (цвет) и порядок «сначала красные».
3. Сверка между документами: ФИО (с транслитерацией), дата рождения, номер паспорта внутри патента и миграционной карты, ФИО из анкеты против ФИО в документе.
4. Истекающие документы: список и выгрузка в XLSX/CSV.
5. Выгрузка карточки соискателя в файл для кадров: XLSX и JSON (PDF — P2).
6. Очередь в цифрах: ждёт, разбирается, разобрано за час, среднее и p95 время.
7. Обезличивание: размытие лица в превью и списках, маскирование номеров документов и email в списке, оригиналы только по клику и с записью в журнал.
8. История по заявке: кто и когда что менял (было → стало).
9. Второй источник (olmOCR), арбитр по вырезке, подсказки по контрольной сумме.
10. Шифрование файлов в S3 (AES-256-GCM, конвертное).
11. Роль БД приложения без права менять журнал (только INSERT и SELECT на `audit_events`).

### P2 — сверх ТЗ, полезное для прода (делать, только если P0 и P1 готовы)

1. Страница соискателя на трёх языках: русский, узбекский (латиница), английский.
2. Раздел «Сотрудники» для `supervisor`: завести сотрудника, выдать роль и офис прямо из нашего интерфейса через Keycloak Admin API. На защите судьи заводят своих сотрудников за минуту.
3. Клавиатурный режим оператора: `J`/`K` — следующее и предыдущее поле, `N` — следующее красное или жёлтое, `Enter` — сохранить, `Esc` — отменить.
4. Детектор повторной заявки: тот же файл (SHA-256) в другой заявке — замечание для `supervisor`.
5. Баннер «распознавание приостановлено». Если модель недоступна, задачи ждут и не сжигают попытки (circuit breaker). Приём продолжается.
6. Сроки хранения и кнопка «удалить данные соискателя» (152-ФЗ): физическое удаление из БД и S3, в журнале остаётся запись без ПДн.
7. Back-channel logout от Keycloak.
8. Выгрузка карточки в PDF.
9. Эндпоинт метрик Prometheus (только внутри сети) и хеш-цепочка журнала аудита.

## Условия допуска Д1–Д12 и чем они закрываются

| Д | Условие | Чем закрываем | Проверка |
|---|---|---|---|
| Д1 | Стенд поднимается по инструкции | Один `docker compose up -d --build`, realm Keycloak импортируется сам, миграции при старте | Прогон README на чистом клоне |
| Д2 | Отдельный бэкенд, проверка входящего на нём | FastAPI владеет данными, фронтенды — статика | Тесты приёма через API в обход UI |
| Д3 | Свои интерфейсы соискателя и оператора | Два React-приложения | `make e2e-smoke` |
| Д4 | Данные переживают перезапуск | PostgreSQL + SeaweedFS на volume | `docker compose restart` → данные на месте |
| Д5 | Разбор реально моделью | Qwen3.8 по изображению, имя файла не передаётся | Журнал: провайдер, модель, длительность на каждый разбор |
| Д6 | Изоляция модели, провайдер в конфиге, локальный провайдер, инструкция | `app/llm/`, `LLM_BASE_URL`, профиль `llm-local` с vLLM, `docs/local-model.md` | Переключение адреса на защите |
| Д7 | Фон, промежуточные стадии, не теряется | Очередь `jobs`, стадии в статусе, reaper | `make restart-drill` |
| Д8 | Вход оператора, нет данных по прямой ссылке | Keycloak + BFF, cookie `__Host-Http-`, проверки на сервере | Автотест 401 по всем маршрутам |
| Д9 | Репозиторий, история, нет секретов | Маленькие коммиты, gitleaks, `.env.example` | `gitleaks detect` |
| Д10 | Документация п. 5.5 | `docs/templates/` → заполненные файлы | Чек-лист в TASKS |
| Д11 | Все восемь видов разбираются на открытом наборе | Реестр восьми видов, `make eval` | Отчёт eval |
| Д12 | Каждый объясняет свой код | Карта владения, `docs/how-to-change.md`, handoff | Люди читают свой модуль |

## Что сознательно не делаем

Интеграцию с внешними учётными системами, проверку подлинности документов по госбазам, обучение моделей, страны и документы вне списка, регистрацию соискателя.
