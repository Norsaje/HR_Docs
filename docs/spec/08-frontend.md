# 08. Фронтенд: два интерфейса

Оба приложения — React 18 + Vite + TypeScript + Mantine 7 + TanStack Query, без внешних CDN. Данные только с сервера (никаких заготовленных экранов). Типы API — из OpenAPI (`make api-types` → `src/api/schema.d.ts`).

Общие правила:

- **Состояние видно всегда.** Загрузка — скелетоны. Пусто — объяснение, что делать. Ошибка — русский текст с сервера и `support_id` мелко.
- **Никаких технических кодов**, `undefined`, англоязычных сообщений и стектрейсов в интерфейсе.
- **Даты** — `ДД.ММ.ГГГГ`, время — `ЧЧ:ММ` по Москве, относительное время — «2 мин назад».
- **Статусы** — цвет + иконка + текст: цвет никогда не единственный носитель смысла.
- **Доступность:** контраст, фокус, подписи у полей, `aria-live` для статусов.

## Приложение соискателя `web/applicant` (телефон в руке, mobile-first)

Маршруты:

- `/` и `/apply/:office` — новая заявка;
- `/a/:applicationId` — заявка по ссылке, токен во фрагменте `#t=`;
- `/legal/*.html` — статика согласия и политики.

### Экран 1. «Кто вы»

- **Офис** — из ссылки, показывается сверху.
- **Страна (гражданство):** выбор с поиском, список с сервера. Подсказка: «От страны зависит список документов».
- **Фамилия, имя, отчество:** одно поле, «как в паспорте».
- **Email:** «Пришлём ссылку на заявку и сообщим, если чего-то не хватит».
- **Галочка согласия** (не отмечена): «Я даю согласие на обработку персональных данных» со ссылками «Согласие» и «Политика обработки персональных данных», открываются в новой вкладке.
- **Кнопка «Продолжить».** Пока нет галочки, она неактивна, но сервер всё равно проверяет. Ошибки сервера показываются у полей.

После создания заявки:

- токен сохраняется в `localStorage['app:'+id]`;
- URL меняется на `/a/:id` без токена;
- в браузере остаётся только `localStorage`.

### Экран 2. «Документы»

Карточка на каждый требуемый документ (из `requirements`):

- название, подсказка из реестра, статус-бейдж;
- кнопки «Сфотографировать» (`<input type=file accept="image/*" capture="environment" multiple>`) и «Выбрать файл» (`accept="image/*,application/pdf,.heic,.heif"`);
- миниатюры загруженных файлов (с сервера, с размытым лицом) и статус каждого: прогресс загрузки → «Принят» / «Отклонён: причина» / «Похоже, этот снимок уже загружен» (предупреждение).

Загрузка:

- каждый файл уходит сразу, отдельным запросом, через `XMLHttpRequest` ради прогресса;
- можно выбрать несколько файлов сразу;
- клиентская проверка размера и типа — только чтобы не ждать: сервер проверяет всё сам.

Внизу:

- «Не хватает: …» — список обязательных документов без принятых файлов;
- **«Отправить комплект»**. Если чего-то не хватает, кнопка всё равно доступна с предупреждением «Можно дослать позже по ссылке из письма».

### Экран 3. «Заявка принята»

- Сразу после нажатия: «Заявка A-2610-0042 принята. Ссылка отправлена на iv***@mail.ru». Ответ сервера мгновенный, разбор не ждём.
- Ниже — список документов с живыми статусами (SSE):
  - **Принят** — «Файл получен, ждёт разбора»;
  - **Разбирается** — «Читаем документ (этап 2 из 4)» с прогрессом по этапам;
  - **Готово** — «Разобран»;
  - **Есть замечания** — безопасный текст: «Срок действия патента истёк. Документ принят, оператор свяжется с вами»;
  - **Не прочитался** — причина и совет, кнопка «Загрузить другое фото»;
  - **Ошибка разбора** — «Сервис распознавания временно недоступен. Мы повторим автоматически».
- Блок «Чего не хватает» с кнопками дозагрузки прямо в карточке документа: та же заявка, без начала заново.
- При потере SSE — переподключение с бэкоффом и полный GET. Маленький индикатор «нет связи, обновим автоматически».

### P2: язык

Переключатель RU / O'zbek / English вверху. Словари лежат в `src/i18n/*.json`. Тексты ошибок с сервера приходят по-русски; для узбекского и английского сервер принимает `Accept-Language` и отдаёт `message` из тех же каталогов (по умолчанию — ru).

## Приложение оператора `web/operator` (компьютер, ширина от 1280 px)

Вход:

- при загрузке — `GET /api/auth/me`;
- 401 → редирект на `/api/auth/login?return_to=<текущий путь>`;
- 403 «нет ролей» → страница «Нет доступа. Обратитесь к руководителю».

Шапка: название, раздел, ФИО, роль по-русски, офис и кнопка «Выйти».

Навигация: «Заявки», «В работе», «Истекающие», «Журнал» (supervisor), «Сотрудники» (supervisor, P2). Пункты, на которые нет прав, не показываются — но сервер всё равно проверяет.

### «Заявки» (список)

- **Фильтры над таблицей**, состояние в URL:
  - статус заявки (мультивыбор);
  - группа стран и страна;
  - офис (только supervisor);
  - «есть ошибки»;
  - «истекает в ближайшие N дней»;
  - поиск: номер заявки или ФИО;
  - период создания.
- **Таблица:** номер, создана, ФИО, страна, офис, статус, чипы документов, счётчик ошибок и предупреждений, ближайшее истечение. Чипы — цветной кружок по худшему полю и короткое имя документа.
- Сортировка по дате (новые сверху), пагинация.
- По SSE `application.updated` таблица перезапрашивается (не чаще раза в 2 секунды).
- Строка с ошибками помечена слева красной полосой.

### Карточка заявки — главный экран

Три колонки.

**1. Документы заявки** (260 px):

- слоты со статусом и цветом;
- блок «Сверка между документами» с замечаниями;
- блок «Данные анкеты»: ФИО, страна, email полностью (раскрывается по клику, событие в журнал).

**2. Оригинал** (гибкая ширина):

- изображение страницы с зумом (колесо, кнопки), перетаскиванием и поворотом на 90°;
- переключение файлов и страниц документа;
- рамка выбранного поля подсвечивается (bbox 0–1000 → проценты, абсолютно позиционированный div поверх img);
- кнопка «Открыть оригинал» скачивает исходный файл, это событие в журнал;
- фото владельца по умолчанию размыто (P1), кнопка «Показать фото».

**3. Поля** (420 px):

- **Строка поля:** подпись, значение, цветная точка с подписью («проверено МЧЗ», «совпало с OCR», «прочитал один источник», «нужно проверить»), источник («модель» или «правка: Правкин О., 13:42»).
- **Под строкой по клику:**
  - кандидаты (Qwen / OCR / арбитр / МЧЗ);
  - подсказка по контрольной сумме («возможно, 8 вместо 3» — кнопка «Подставить», это тоже правка оператора);
  - сигналы.
- **Правка** (doc-editor): клик по значению → инпут → `Enter` сохраняет, `Esc` отменяет. Ошибка формата приходит с сервера и показывается под полем. После сохранения правила пересчитываются, замечания обновляются.
- **Порядок:** сначала красные, потом жёлтые, потом зелёные, внутри — в порядке реестра. Переключатель «по порядку документа».
- **Замечания документа:** ошибки красным, предупреждения жёлтым, инфо серым.
- **Кнопки** (по правам): «Разобрать повторно», «Отметить проверенным», «Запросить документы у соискателя» (модалка с комментарием), «Выгрузить карточку» (XLSX/JSON).

Вкладки над колонками: **«Документы»** | **«История»** (журнал заявки: кто, когда, что, было → стало) | **«Технические детали»** (supervisor: `extraction_runs` — провайдер, модель, версия промпта, длительность, попытка).

**P2 — клавиатура:**

| Клавиша | Действие |
|---|---|
| `J` / `K` | следующее / предыдущее поле |
| `N` | следующее красное или жёлтое |
| `E` | править |
| `Enter` | сохранить |
| `Esc` | отменить |
| `V` | отметить документ проверенным |

Подсказка по клавишам — по `?`.

### «В работе»

- **Карточки-счётчики** (из `/api/operator/queue`, обновление по SSE `queue.updated` и раз в 5 секунд): «Ждут разбора», «Разбираются сейчас», «Разобрано за час», «Ошибки за час», «Среднее время разбора», «p95», «Самая старая задача ждёт».
- **Таблица «Разбираются сейчас»:** заявка, документ, этап, воркер, сколько идёт, попытка.
- **Таблица «Ждут»:** позиция, заявка, документ, сколько ждёт.
- **Таблица «Ошибки»:** заявка, документ, причина по-русски, кнопка «Повторить» (doc-editor).
- **Баннер статуса модели:** «Распознавание работает (Qwen3.8, llm.ilons.ru)» или «Распознавание приостановлено: модель недоступна с 13:40. Документы ждут в очереди».
- Пустое состояние: «Сейчас ничего не разбирается».

### «Истекающие»

- Список документов, истекающих в ближайшие N дней (по умолчанию 30) и уже истёкших.
- Колонки: соискатель, документ, дата, «осталось дней», офис.
- Кнопки «Выгрузить XLSX» и «CSV».

### «Журнал» (supervisor)

Таблица `audit_events` с фильтрами: актор, действие, результат, период, заявка. Отказы подсвечены.

### «Сотрудники» (supervisor, P2)

- Список пользователей realm: ФИО, логин, роль, офис, включён.
- «Добавить сотрудника»: ФИО, логин, email, роль (одна из трёх), офис, временный пароль (генерируется и показывается один раз).
- Включить/выключить сотрудника.

## Обработка ошибок на фронтенде

- **Одна функция `apiFetch`:**
  - добавляет `X-Requested-With: hr-operator` (оператор) или `X-Application-Token` (соискатель);
  - разбирает `{error}`;
  - 401 у оператора → редирект на логин; 401 у соискателя → экран «Ссылка устарела».
- **Сетевая ошибка** → «Нет связи с сервером. Проверьте интернет — повторим автоматически».
- **ErrorBoundary** на корне: «Что-то пошло не так. Обновите страницу» и `support_id`, если он есть.
