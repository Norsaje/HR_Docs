# 10. Оценка качества, эксплуатация, сценарий защиты

## Оценка качества (`eval/`)

Блок «Качество разбора» (30 баллов) обнуляется, если на закрытом наборе качество резко падает. Защита одна: мерить себя так же, как судьи, — на документах, под которые ничего не настраивали.

### Данные

- Открытый набор лежит в `data/open/<doc_type>/*` (в `.gitignore`). Если структура набора другая, напиши адаптер `eval/dataset.py`.
- Эталон — `eval/gold/<sha256-файла>.json`: `{"doc_type": "...", "fields": {"series": "4509", ...}, "unreadable": false}`. Значения нормализованы так же, как в `06-documents.md`. Ключ — хеш, а не имя файла.
  - Эталон размечают люди, по одному виду документов на человека. Агент может сделать черновик (прогнать модель), но человек проверяет каждое значение и ставит `"reviewed_by": "<имя>"`.
  - Если набор содержит реальные ПДн, эталон не коммитить.
- Сплит `eval/split.py`: детерминированно по `sha256`, примерно треть каждого вида — в holdout. **На holdout промпты и пороги не настраиваются.**
- Искажения `eval/distort.py` (для holdout):
  - поворот ±3°, 90° и 180°;
  - перспектива;
  - JPEG q=35 (как в мессенджере);
  - уменьшение до 900 px;
  - гауссово размытие σ=1.5;
  - блик (белый эллипс 30% прозрачности).

### Запуск

`make eval [SPLIT=dev|holdout|distorted|all] [LIMIT=N]`. Скрипт `eval/run.py` вызывает пайплайн как библиотеку (тот же код, что у воркера), без API и очереди. Кэш ответов модели — в `eval/cache/` (gitignored), с флагом `--no-cache`.

### Метрики (`eval/metrics.py`) → отчёт `eval/reports/YYYYMMDD-HHMM-<git-sha>.md` (коммитится)

| Метрика | Определение |
|---|---|
| Точность поля | точное совпадение после нормализации, по видам документов и полям |
| Документ разобран | все поля минимума извлечены и верны |
| Ложные зелёные | зелёное поле с неверным значением. Цель — 0 |
| Доля зелёных | сколько работы снимаем с оператора |
| Честные отказы | на заведомо непригодных копиях — доля `unreadable` с причиной (а не выдуманных полей) |
| Галлюцинации | значение при эталоне `null` (поля нет или не видно) |
| Разрыв dev ↔ holdout | разница точности; большой разрыв — признак подгона |
| Латентность | p50/p95 секунд на документ, по провайдеру |
| Доля повторов | доля вызовов, потребовавших повтора по схеме |

Сравнение провайдеров (`PROVIDER=ilons|local`) даёт таблицу для ответа по п. 5.3.9: скорость, качество, железо.

## Журнал и наблюдаемость

- **Журнал аудита:** что пишется — в `03-data-model.md`. Экран — «Журнал» (supervisor) и вкладка «История» в карточке.
- **Обязательные тексты журнала** (примеры):
  - «Соискатель по ссылке загрузил файл в документ «Паспорт РФ» — принят»;
  - «… — отклонён: файл больше 20 МБ»;
  - «Воркер worker-1 начал разбор файла … (попытка 1, Qwen3.8 @ llm.ilons.ru)»;
  - «Разбор завершён за 12,4 с: 9 полей, 7 зелёных, 2 жёлтых»;
  - «Модель не ответила за 90 с — повтор через 30 с»;
  - «Задача возвращена в очередь: воркер перестал отвечать»;
  - «Оператор Правкин О. исправил поле «Номер»: 123456 → 128456»;
  - «Отказ в доступе: Невская А. пыталась открыть заявку другого офиса».
- **Технические логи** — JSON, без ПДн.

## Эксплуатация

- **Миграции:** `alembic upgrade head` при старте api (под `hr_owner`). Воркер ждёт, пока api не станет healthy.
- **Если модель недоступна,** приём продолжается: задачи ждут с backoff, оператор видит баннер. После восстановления разбор продолжается сам.
- **Резервные копии (P2):** `make backup` — `pg_dump` и копия volume S3 в `backups/` (gitignored). `make restore`. Проверка восстановления — в `docs/limitations.md`, если не успели.
- **Обновление промпта:** новая версия файла `prompts/extract.v2.md` и `PROMPT_EXTRACT_VERSION=v2` в `.env` — только после `make eval` без регресса.

## Сценарий защиты (прогнать заранее, текстом в `docs/demo.md`)

1. `docker compose ps`: все сервисы healthy. Наружу открыт только 443.
2. **Соискатель с телефона** (Узбекистан):
   - список документов подстроился;
   - снимаем паспорт камерой;
   - загружаем тот же файл второй раз → «уже загружен»;
   - переименованный `.exe` → «тип файла не подходит»;
   - «Отправить» → мгновенное подтверждение, статусы бегут.
3. **Оператор:**
   - вход через Keycloak → список;
   - карточка: оригинал рядом с полями, подсветка рамки, цвета, кандидаты;
   - правка поля → «правка оператора», запись в «Истории».
4. **Просроченный патент:** принят, ошибка «срок истёк», виден в «Истекающие» → выгрузка XLSX.
5. **«В работе»:** загрузить 20 файлов и показать очередь в цифрах; `docker compose kill worker` → `up -d worker` → все 20 дошли (журнал: «задача возвращена в очередь»).
6. **Модель недоступна:** `LLM_BASE_URL` на несуществующий адрес → честная «ошибка разбора» и баннер; вернуть адрес → «Разобрать повторно».
7. **Переключение на vLLM на A10:** `make switch-llm TARGET=local`, новый документ, в технических деталях `vllm`.
8. **Безопасность:**
   - `curl` к `/api/operator/applications` без cookie → 401;
   - `editor.spb` открывает ссылку на заявку Москвы → 404;
   - `doc-reader` не видит кнопок правки, а прямой PATCH → 403.
9. **Новый сотрудник:** supervisor заводит его в «Сотрудники» (или в админке Keycloak через туннель), сотрудник входит.
10. **Правка за 10 минут:** добавить поле, правило или фильтр по `docs/how-to-change.md`.
