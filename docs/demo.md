# Сценарий защиты и покрытие критериев

<!-- Статусы: готово / частично / нет. «Чем проверено» — команды, которые реально запускались 10.10.2026. -->

## Сценарий защиты (коротко)

1. `docker compose ps` — все сервисы healthy; наружу открыты только 80/443 (8081 и 8025 — на 127.0.0.1).
2. Соискатель: https://localhost → страна → ФИО, email, согласие → набор документов страны → загрузка (по каждому файлу «принят / отклонён: причина») → тот же файл ещё раз → «Этот файл уже загружен» → «Отправить комплект» → номер заявки → статусы обновляются каждые 2 с → «Не хватает: …» → дозагрузка по той же ссылке.
3. Оператор: https://localhost/operator/ → вход через Keycloak (editor.msk, пароль = KC_DEMO_PASSWORD из .env) → список → карточка: изображение и поля с цветом, клик по полю — рамка на изображении, сначала красные → правка поля → вкладка «История».
4. «В работе»: `make restart-drill` (или `make open-set`) — очередь в цифрах; `docker compose kill worker` → `up -d worker` → в журнале «Задача … возвращена в очередь: воркер перестал отвечать», все файлы доходят.
5. Модель недоступна: в `.env` `LLM_BASE_URL` на несуществующий адрес → `docker compose up -d worker` → после повторов «Ошибка разбора» с понятной причиной → вернуть адрес → «Разобрать повторно».
6. Безопасность: `curl -k https://localhost/api/operator/applications` → 401; editor.spb открывает заявку Москвы → 404; reader.msk правит поле → 403.
