# Ограничения и планы

Сдаваемая версия собрана в аварийном режиме за ограниченное время. Приоритет — обязательный объём (Д1–Д12); всё, что ниже, сознательно вырезано или упрощено.

## Не успели (вырезано)

- **olmOCR в пайплайне разбора.** Второй независимый источник проверен экспериментом 1 (хорошо читает кириллицу), провайдер `olmocr_http` и метод `Gateway.ocr` есть и покрыты тестами, но в разбор документа не подключены. Следствие: зелёными становятся только поля, подтверждённые контрольной суммой; остальные прочитанные поля — жёлтые.
- **Арбитр по вырезке (проход C)** и голосование 2 из 3 — не реализовано (промпт `prompts/arbiter.v1.md` и `Gateway.arbitrate` есть, в пайплайн не подключены).
- **Разбор и сверка МЧЗ** (паспорта, ID-карты) — не реализовано.
- **Шифрование файлов в S3** (AES-256-GCM, конвертное) — не реализовано; файлы лежат в бакете без публичного доступа, ключ объекта — UUID.
- **Письма соискателю** (Mailpit поднят, но отправка не реализована).
- **Размытие лица в превью** (YuNet) — не реализовано; оригиналы и страницы отдаются только с сессией оператора, просмотр пишется в журнал.
- **SSE** заменён опросом `GET` раз в 2 секунды (соискатель) и 3 секунды («В работе»).
- **Оценка качества `make eval`**: эталонной разметки `eval/gold/` нет, сплита dev/holdout и искажённых копий нет. Есть только эксперименты фазы 0 (`eval/reports/`), где правильность номеров меряли контрольными суммами, остальное — согласием Qwen и olmOCR.
- **Make-цели** `api-types`, `eval`, `switch-llm` печатают «не реализовано». Есть скрипты `make e2e-smoke` (`scripts/e2e_smoke.py`), `make restart-drill` и `make open-set` (`scripts/run_open_set.py`), `make llm-smoke` (`app/llm/smoke.py` внутри контейнера worker).
- **P2** целиком: языки, раздел «Сотрудники», клавиатурный режим, circuit breaker, детектор повторной заявки, сроки хранения и удаление данных, back-channel logout, PDF-выгрузка, метрики Prometheus.
- Из проверок качества кадра до вызова модели есть только «слишком тёмное фото» (средняя яркость); резкость и блики не проверяются — решение «нечитаемо» по ним принимает модель (статус поля `unreadable`).

## Работает частично

- **vLLM на A10 (профиль `llm-local`) не проверен.** Демо и разработка — на Windows-машине с Docker Desktop без GPU. Файлы профиля и инструкция есть (`infra/llm/`, `docs/local-model.md`), запуск на сервере с A10 и замеры — следующий шаг.
- **Проверено на открытом наборе без эталона:** `make restart-drill` / `make open-set` — 46 файлов, воркер убит посреди разбора, 46/46 дошли до финального статуса, все 8 видов набора разобраны (ready / needs_review; тёмное фото → «не прочитался»). Точность полей не измерена — эталона нет.
- **Виды документов.** Реестр содержит 8 видов спецификации и 4 вида из открытого набора (ВУ РФ, ВУ Киргизии, паспорт Беларуси, паспорт Индии). Для видов спецификации без образцов в наборе (паспорт Узбекистана, миграционная карта, документ ЕС, ВНЖ) разбор проверен только на совместимость схемы (эксперимент 3), не на реальных документах.
- **Цвет уверенности** — упрощённое правило: зелёный только при «твёрдом» подтверждении (контрольная сумма ИНН/СНИЛС или совпадение с текстовым слоем PDF) и печатном тексте; нет сигналов резкости области поля и согласия с OCR.
- **Бонусы** (сверка ФИО и даты рождения между документами, выгрузка карточки в JSON/CSV, истекающие документы с CSV, маскирование email и номеров в списке) сделаны в минимальном виде; актуальное состояние — в `docs/demo.md`.
- **Сессия оператора:** cookie `__Host-Http-hr_session` с `SameSite=Lax` (а не `Strict`, как в спецификации: со `Strict` cookie не приходит после редиректа из Keycloak); обновление ролей через refresh_token раз в 5 минут не реализовано — роли берутся при входе.
- Все коммиты — под одной git-идентичностью; ревью модулей владельцами по карте из `docs/TASKS.md` — за командой.

## Стенд на сервере с доменом — не развёрнут

Инструкция готова (README, раздел «Развёртывание на сервере с доменом»: домен `<IP-с-дефисами>.sslip.io`, Let's Encrypt через Caddy, всё через `.env`). Стенд для защиты работает на ноутбуке (`https://localhost`). На GPU-сервере его развернуть не удалось, потому что:

- **нет доступа по SSH:** сервер отвечает `Permission denied (publickey)` для выданного ключа: публичная часть ключа не добавлена в `authorized_keys` пользователя на сервере. Кроме того, приватный ключ защищён паролем, а пароля у агента нет;
- **порт 443 снаружи закрыт** (проверка с ноутбука: таймаут соединения). На порт 80 соединение принимается, но ответ пустой: похоже, его перехватывает сетевое оборудование провайдера. Для домена с сертификатом Let's Encrypt нужно открыть входящие 80 и 443 до сервера;
- что сделать: добавить публичный ключ в `~/.ssh/authorized_keys` на сервере, открыть 80/443 в настройках облака или сетевого экрана, затем пройти README по шагам. Если открыть порты нельзя — `CADDY_TLS=internal` и доступ через `ssh -L 443:localhost:443`.

## Следующие 10 часов

1. Подключить olmOCR как второй голос и арбитра по вырезке — больше зелёных полей без ложных.
2. Разметка эталона и `make eval` с holdout и искажёнными копиями; ноль ложных зелёных как гейт для правки промптов.
3. Запустить профиль `llm-local` на A10, замерить скорость и качество, `make switch-llm`.
4. Проверка качества кадра до модели (резкость, блики, темнота) с понятными советами соискателю.
5. Шифрование файлов в S3, письма соискателю, SSE вместо опроса.
6. MFA (TOTP или passkeys) для операторов, резервное копирование с проверкой восстановления.

## Дорога до прода

Пилот в одном офисе; модель FP8 на GPU 80 ГБ; egress-прокси с allowlist для воркера; ключи в KMS/Vault; оценка уровня защищённости ИСПДн по ПП № 1119; тексты согласия и политики согласовать с юристом.
