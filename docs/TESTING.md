# Ручная проверка стенда

Коротко, по шагам. У каждого шага — что сделать и что **должно** получиться. Если не так — запишите баг строкой из конца файла.

## Перед началом

```bash
docker compose up -d --build     # стенд; все сервисы должны стать healthy: docker compose ps
make e2e-smoke                   # сквозная проверка, в конце «e2e-smoke: всё зелёное»
make test-files                  # тестовые файлы в data/test/
make demo-seed                   # 3 демо-заявки (RU, UZ, BY) через настоящий API и модель
```

| Что | Адрес | Вход |
|---|---|---|
| Страница соискателя | https://localhost/ | без входа (сертификат самоподписанный — «Всё равно перейти») |
| Рабочее место оператора | https://localhost/operator/ | `editor.msk`, `reader.msk`, `editor.spb`, `supervisor`; пароль — значение `KC_DEMO_PASSWORD` в `.env` |
| Письма (Mailpit) | http://127.0.0.1:8025 | без входа |
| Админка Keycloak | http://localhost:8081/kc/admin | `KC_BOOTSTRAP_ADMIN_USERNAME` / `KC_BOOTSTRAP_ADMIN_PASSWORD` из `.env` |

Файлы в `data/test/`: `01…16_<вид>_*.jpg|pdf` — хорошие документы каждого вида; `fake.jpg` — текст под видом фото; `big.jpg` — 21 МБ; `blurry.jpg`, `dark.jpg` — испорченные копии паспорта РФ; `wrong_page.jpg` — страница прописки; `receipt.jpeg` — чек; `expired_*` — документы, у которых модель прочитала истёкший срок.

## Соискатель (С1–С6)

- [ ] **Страна → набор.** На https://localhost/ в поиске страны введите «Росс» → выберите Россию. Ожидается: внизу «Понадобятся документы:» — Паспорт РФ, СНИЛС, ИНН, ВУ РФ (необязательно). Смените на Узбекистан → паспорт Узбекистана, миграционная карта, патент; Беларусь → паспорт Беларуси.
- [ ] **Анкета.** Россия, ФИО, email, галочку согласия НЕ ставить → «Продолжить». Ожидается: заявка не создаётся, просьба отметить согласие. Отметьте → переход к шагу «Документы».
- [ ] **Несколько файлов в один документ.** В «Паспорт РФ» → «Выбрать файл» → `01_ru_passport_1.jpg` и `02_ru_passport_2.jpg`. Ожидается: у каждого файла прогресс и «принят».
- [ ] **Дубликат.** Ещё раз `01_ru_passport_1.jpg` в тот же документ. Ожидается: «отклонён: Этот файл уже загружен в заявку».
- [ ] **Не картинка.** `fake.jpg` в «СНИЛС». Ожидается: «Тип файла не подходит. Загрузите фото (JPEG, PNG, WebP, HEIC) или PDF».
- [ ] **Слишком большой.** `big.jpg`. Ожидается: отказ «Файл больше 20 МБ…» (подсказка появляется уже в браузере, сервер проверяет тоже).
- [ ] **Отправка.** Загрузите `03_snils_1.jpg` в СНИЛС, ИНН не загружайте → «Отправить комплект». Ожидается: мгновенно номер заявки (кнопка «Скопировать номер») и блок «Не хватает: ИНН физического лица».
- [ ] **Статусы без перезагрузки.** Не трогая страницу, смотрите на документы: «В очереди» → «Подготовка изображения» → «Читаем документ» → «Проверяем данные» → «Готово» / «Есть замечания» (≈ 15–40 с на документ).
- [ ] **Дозагрузка по ссылке из письма.** Откройте Mailpit → письмо «Заявка A-… принята» → ссылка. Ожидается: та же заявка; в блоке «Не хватает» — «Дозагрузить» → `05_inn_1.jpg` → ИНН появляется в той же заявке. Перезагрузка страницы возвращает на заявку.
- [ ] **Письмо «не хватает».** Если после разбора по обязательному документу «Не прочитался» или документа нет, в Mailpit приходит письмо «Заявка A-…: не хватает документов» (не чаще раза в 10 минут на заявку).

## Разбор (С7–С10)

- [ ] **Все виды.** `make open-set` прогоняет весь открытый набор через API (≈ 3 мин) и печатает статусы по видам; или загружайте файлы `01…16` вручную в заявки нужных стран (КГ — Киргизия, BY — Беларусь, IN — Индия, патент — Узбекистан).
- [ ] **Истёкший срок.** Заявка Беларуси с `expired_by_passport_1.jpg`. Ожидается: документ принят, статус «Есть замечания», у оператора замечание «Срок действия паспорта истёк …», документ в «Истекающих».
- [ ] **Нечитаемо.** `blurry.jpg` и `dark.jpg` в «Паспорт РФ». Ожидается: «Не прочитался» с причиной и советом (модель на них не вызывается).
- [ ] **Не тот документ.** `receipt.jpeg` в «ИНН» или `wrong_page.jpg` в «Паспорт РФ». Ожидается: у оператора замечание «В слот … загружен другой документ» или «На фото не найден документ».
- [ ] **Модель недоступна.**
  ```bash
  cp .env .env.bak
  sed -i 's#^LLM_BASE_URL=.*#LLM_BASE_URL=https://llm.invalid/v1#' .env
  docker compose up -d worker
  ```
  Загрузите документ. Ожидается: соискатель видит «Ошибка разбора — повторим автоматически» / «в очереди»; оператор в «В работе» — «Распознавание приостановлено» и задачу в «Ждут повтора» с причиной; значений полей нет. Через ≈ 7 мин (5 попыток с паузой 30→240 с) документ — «Ошибка разбора». Вернуть:
  ```bash
  mv .env.bak .env && docker compose up -d worker
  ```
  Затем в карточке «Разобрать повторно» → документ разбирается.

## Устойчивость (С11–С12)

- [ ] ```bash
  make open-set &          # 46 файлов в очередь
  sleep 20; docker compose kill worker; sleep 5; docker compose up -d worker
  ```
  Ожидается: в «В работе» растут «ждут» и «разбирается», после kill задачи возвращаются в очередь (в журнале заявки: «Задача … возвращена в очередь: воркер перестал отвечать»), в конце все файлы в финальном статусе. То же автоматически: `make restart-drill`.

## Оператор (С13–С18)

- [ ] **Вход.** https://localhost/operator/ → форма Keycloak → `editor.msk`. Ожидается: список заявок офиса «Москва»; email замаскирован (`d***@example.test`).
- [ ] **Фильтры.** Статус, страна, поиск по ФИО или номеру, «Только с ошибками». Фильтры сохраняются в адресе страницы.
- [ ] **Карточка.** Откройте демо-заявку России. Ожидается: слева документы (и «Не загружены»), в центре изображение (по умолчанию превью с размытием; «Показать оригинал» — читаемое, просмотр пишется в журнал), справа поля: сначала красные, потом жёлтые, зелёные. Зум, «Повернуть», перетаскивание.
- [ ] **Рамка.** Клик или наведение на поле — на изображении подсвечивается его рамка. Под полем — почему такой цвет (например, «подтверждено контрольной суммой», «прочитал только один источник — нужно проверить») и «Как напечатано».
- [ ] **Цвета.** Зелёный — подтверждено независимой проверкой (контрольная сумма, МЧЗ, текст PDF, совпадение с OCR); жёлтый — стоит взглянуть; красный — не прочитано или нарушено правило; серый — поля нет на документе.
- [ ] **Правка.** «Изменить» (или E) → новое значение → Enter. Ожидается: бейдж «правка оператора: Олег Правкин, время», правила пересчитаны; вкладка «История» — «исправил поле «…»: было → стало».
- [ ] **Повторный разбор / проверено / перенос.** «Разобрать повторно» → документ снова в очереди; «Отметить проверенным» (V); «Перенести файл в…» — в другой слот.
- [ ] **Запросить документы.** «Запросить документы» → выбрать документы, комментарий → письмо в Mailpit.
- [ ] **Выгрузка.** «Выгрузить JSON» / «Выгрузить CSV» — файл карточки.
- [ ] **«В работе».** Плитки: ждут, разбирается, разобрано за час, ошибок за час, среднее и p95, самая старая задача; таблицы «Разбирается сейчас», «Ждут повтора», «Упавшие».
- [ ] **«Истекающие».** Список документов со сроком в ближайшие N дней и уже истёкших; «Скачать CSV».
- [ ] **Права.** Выйти → войти `reader.msk`: кнопок правки нет. `editor.spb`: заявок Москвы не видно, прямая ссылка на заявку Москвы → «не найдено».
- [ ] **Без входа.** В приватном окне откройте `https://localhost/api/operator/applications` → `{"error":{"code":"UNAUTHORIZED",…}}` (401); ссылка на файл `…/api/operator/files/<id>/pages/1` → 401.
- [ ] **Горячие клавиши.** В карточке: J/K — следующее/предыдущее поле, N — следующее красное/жёлтое, E — править, V — проверено, ? — подсказка.
- [ ] **Вход владельца по email.** Логин — ваш email (заведён `make kc-user`), роль supervisor, пароль — значение `KC_DEMO_PASSWORD` из `.env` (политика Keycloak — не короче 12 символов).
- [ ] **Редактор добавляет оператора.** `editor.msk` → «Сотрудники» → «Новый сотрудник» с ролью «Просмотр» или «Редактор» и офисом «Москва» → создан. Роль «Руководитель» или офис «Санкт-Петербург» → «Недостаточно прав». Новый оператор входит, Keycloak просит сменить временный пароль, после этого видит заявки своего офиса.
- [ ] **Вход через Google** — включается командой `make kc-google` после того, как в `.env` вписаны `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` (OAuth-клиент Google, redirect URI печатает сама команда). Без ключей кнопки нет. Сотрудник с тем же email привязывает Google к своей учётке при первом входе.
- [ ] **Сотрудники (supervisor).** Войти `supervisor` → «Сотрудники» → «Новый сотрудник» (логин, ФИО, email, роль, офис, временный пароль от 12 символов). Ожидается: сотрудник появился; он входит и Keycloak просит сменить пароль.

## Модель (С19–С20)

- [ ] Слой модели — `backend/app/llm/` (шлюз `gateway.py`, провайдеры `providers/openai_compat.py`, `providers/olmocr_http.py`); адрес и модель — `LLM_BASE_URL`, `LLM_MODEL` в `.env`.
- [ ] `make llm-smoke` → «OK: openai_compat @ llm.ilons.ru, модель …» — проверка текущего адреса из контейнера воркера.
- [ ] Переключение: `make switch-llm TARGET=local` / `make switch-llm TARGET=ilons` (меняет `LLM_*` в `.env`, пересоздаёт worker). **На этом стенде локальный vLLM не поднят** (нет GPU, на GPU-сервер нет доступа по SSH) — переключение на local даст «ошибку разбора»; инструкция подъёма — `docs/local-model.md`.

## Бонусы — где смотреть

| № | Бонус | Где |
|---|---|---|
| 1 | Сообщить, чего не хватает | экран заявки «Не хватает: …» + письма в Mailpit; «Запросить документы» у оператора |
| 2 | Уверенность по полю | цвета полей и пояснения в карточке, сначала красные |
| 3 | Сверка между документами | карточка, блок «Сверка между документами» (ФИО, дата рождения, ФИО анкеты) |
| 4 | Истекающие | раздел «Истекающие» + CSV |
| 5 | Выгрузка карточки | «Выгрузить JSON / CSV» в карточке |
| 6 | Очередь в цифрах | раздел «В работе» |
| 7 | Ограничение доступа к ПДн | маскированный email в списке, превью с размытием, оригинал по клику с записью в журнал, номера маскируются в журнале |
| 8 | История | вкладка «История» в карточке |

Не реализовано: размытие именно лица (сейчас размыто всё превью), SSE (статусы — опрос каждые 2–3 с), стенд с доменом и vLLM на A10 — см. `docs/limitations.md`.
